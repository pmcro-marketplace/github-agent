# github-agent marketplace

Independent marketplace for GitHub agent execution, preserving the canonical
`github` plugin and six upstream skills from the pinned upstream commit.

Authoritative definitions live in `.agents/` and `plugins/github/`.
Generated profiles and test evidence live in `dist/` only.
The .NET runtime uses native MAF AIAgent/Workflow, AGT run middleware and
the official A2A/AG-UI hosting packages. Its GitHub REST capabilities
are scoped to the pmcro-marketplace organization. Read-only public access is
supported; authorized operations may use a host-provided PMCRO_GITHUB_TOKEN.
No token is included in a request, trail or repository.

Supported native operations:
- /github:repository-discovery:get-repository
- /github:actions:inspect
- /github:actions:verify-run
- /github:change-management:create-repository
- /github:actions:dispatch

The two POST bindings require a host-provided credential and one-shot approval
of the exact request, including repository visibility or workflow ID and branch.
See `plugins/github/skills/github/references/write-authorization.md`.
Fixture validation and a live read/denial proof do not prove live writes.
Do not treat a repository, YAML file, or dispatch receipt as a successful run.

Build:
```sh
dotnet build plugins/github/skills/github/scripts/maf/Github.Agent.csproj -p:RestoreLockedMode=true
```

Run proof:
```sh
python plugins/github/skills/github/scripts/prove_native.py dotnet \
  plugins/github/skills/github/scripts/maf/bin/Debug/net10.0/Github.Agent.dll \
  . dist/native-proof
```

The process binds loopback and requires a bearer for A2A and AG-UI.
The native tool execution uses deterministic GET and approved POST calls, not LLM execution.

Open `http://127.0.0.1:PORT/studio` after starting the host with
`PMCRO_MAF_TOKEN` set and enter the local bearer, target repository, and
operation. The UI streams actual returned phase frames.

The managed `.github/` profile is generated by
`plugins/github/skills/github/scripts/generate_profile.py`; it is not native
GitHub/Copilot installation evidence. A candidate remote workflow lives in
`.github/workflows/verify-native.yml`, with build, skill validation, live
native proof, fixture tests, and artifact upload. The authenticated write gate
must be passed separately before provisioning the independent agent repositories.
